## 확정된 서비스 흐름

계정 인증 → 최초 기본정보 입력 → 조회 상태에 따른 업로드/직접 입력 → AI 추출 결과 사용자 확정 → 최초 로드맵 생성 → 현재 업무 안내 → 처리 결과 저장 → 다음 단계 활성화.
기존 사용자는 메인으로 진입합니다. 자료·기본정보 변경은 먼저 저장하고 영향 검사를 수행하며, 중요한 변경만 사용자 확인을 받은 뒤 재분석합니다.

## 반드시 보존할 규칙

- 금액 미확인은 0원이 아니다. 금액 null과 확인 상태를 별도로 관리한다.
- AI 추출값은 사용자 확정 전 재산·채무에 반영하지 않는다.
- 단계 클릭은 탐색만 한다. 완료는 해당 업무의 결과 조건으로 판정한다.
- 일반 결과 저장/완료 취소는 상태와 선행조건을 재계산한다. 매번 AI 재분석하지 않는다.
- 중요 정보 변경 후 승인하지 않으면 기존 로드맵과 변경 미반영 표시를 유지한다.
- 기한은 버전이 있는 고정 규칙으로 계산한다. 기산일 미확정은 확인 필요로 표시한다.
- AI는 정보 추출·절차 선별·정리·위험 신호만 담당하며 법률·세무 결론을 확정하지 않는다.
- 부동산 등 상세 범위 밖 항목도 존재 자체는 보존하고 별도 표시한다.

## Figma 분석

[와이어프레임 페이지](https://www.figma.com/design/cmDRw239zpdF0Uz02ZIBmG?node-id=40-230).
페이지 메타데이터로 화면 구성을 확인하고, 로그인 `43:2`의 디자인 컨텍스트와 스크린샷을 확인했습니다. 각 상세 화면의 시각 검수는 해당 구현 단계에 진행합니다.
390×844 모바일, 좌우 16px, 입력 44px, 기본 버튼 46px, 중립 회색, 8~13px 모서리입니다. 현재 로그인 화면에 반영했고 좁은 화면에서 너비가 줄도록 구성했습니다.
Noto Sans KR은 로컬 설치 시 사용하고 없으면 시스템 한글 폰트로 대체합니다. 최종 폰트 배포는 추후 결정합니다.

명세 우선 적용 사항:

- 와이어프레임의 비밀번호 찾기·마케팅 동의는 명세에 없다. 이번 초기 화면에서는 추가하지 않는다. 약관/개인정보 동의 정책은 가입 구현 전에 별도 결정한다.
- 사망일이 모든 기한의 기준이라는 와이어프레임 문구는 그대로 구현하지 않는다. 명세의 기산일 불확실성 및 상속 인지일 조건을 보존한다.
- 고정 90일 전체 로드맵을 강제하지 않는다. 필요한 단계만 선별하고 선행관계·기한을 반영한다.

## 가안에서 자동 채택하지 않는 기능

가족 초대·역할별 협업·업무 배정, 기관별 서류 패킷 생성, 전문가 연결/상담 보고서, 유료 결제, 금융기관 연동, 문자/이메일 알림, 챗봇은 최종 명세에 없으므로 범위에 넣지 않습니다. 공동상속인 구성 입력은 유지합니다.

## 구현 전 구체화할 사항

1. 기본 단계 카탈로그, 각 완료 조건 및 선행관계, 기한 규칙의 공식 근거와 검토 책임자.
2. 조건부 질문 노출 조건 및 관계·재산·채무 유형 코드 목록.
3. 재분석을 유발하는 변경 목록과 기존 완료 결과를 새 버전에 이관하는 기준.
4. 계정당 사건 수: DB는 다중 사건 가능 구조를 제안하되 MVP UI는 활성 사건 1건을 가정.
5. 문서 허용 크기/페이지 수, AI 제공자·지역·보존 정책, 탈퇴·삭제·계정 복구 정책.
6. 배포 제공자와 도메인. 우선 저장소 하위 경로별 독립 배포를 가정.
